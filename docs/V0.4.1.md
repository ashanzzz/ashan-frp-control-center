# v0.4.1 Node Intelligence, Auth, AI Discovery & Weekly Speed Optimization

## Overview

v0.4.1 adds concurrent real-port TCP latency probing (`crates/node-probe`), ChmlFrp Qzhua OAuth2 SSO + RFC 6238 TOTP 2FA auto-login, node capability/bandwidth/stability tagging, 10-minute FRPC disconnect grace watchdog, mandatory Control Center API Key auth, lightweight AI self-discovery (`/api/v1/capabilities` & `/llms.txt`), `PATCH /api/v1/settings/providers`, one-click `POST /api/v1/nodes/switch-fastest`, and a weekly Sunday 03:00 (UTC+8) automatic speed optimizer.

## Candidate filtering & ranking order

1. **Eligibility filter (`ordered_candidates_with_policy`)**:
   - Excludes `offline`, quarantined, or `被攻击/暂时无法使用` nodes.
   - When `require_web` is true (HTTP/HTTPS tunnels exist), excludes `web_supported = false` nodes.
   - When `probe_require_high_bandwidth` is true, excludes `禁网盘/大流量` & `限速/线路较差` nodes.
   - Optionally excludes `需域名备案` (`probe_exclude_icp_required`), `需加群过白`/`封禁海外IP` (`probe_exclude_whitelist_and_ban_overseas`), and overloaded nodes (`load1 > probe_max_load1`).
2. **Real-port concurrent TCP probe (`probe_and_rank`)**:
   - Concurrently dials `node.host:node.frps_port` (falling back to `probe_port` only when `/nodeinfo.port` is missing; 3 attempts per node).
   - During automatic/weekly switch-fastest, if the active node is already the fastest eligible node (or within `min_improvement_ms`), switching is skipped cleanly without restarting FRPC.
3. **Weekly Sunday 03:00 (UTC+8) optimization & 10-min disconnect watchdog**:
   - Brief transient drops (< `failover_disconnect_grace_secs`, default `600s`) let FRPC reconnect in-place without false 30-day quarantines.
   - Sustained disconnects `>= 600s` (or `>= 60s` confirmed offline/attacked via ChmlFrp API) trigger `GLOBAL_FAILOVER` with automatic fallback to subsequent ranked candidates if target `wait_ready` times out.

## Authentication & AI Self-Discovery

- All `/api/v1/*` routes and `/llms.txt` require `Authorization: Bearer <API_KEY>` or `X-API-Key: <API_KEY>` (SSE `/api/v1/events` accepts `?api_key=<API_KEY>`). Only `/api/v1/health`, `/api/v1/auth/verify`, and the static UI shell are public.
- AI clients can read `GET /api/v1/capabilities` (JSON) or `GET /llms.txt` (Markdown) to discover every endpoint, invariant, and live state (`require_web`, `web_supported`, active/standby, policy settings).

# v0.4.1 Latency-First Node Probe

## Overview

v0.4.1 adds concurrent TCP latency probing (`crates/node-probe`) to global failover candidate selection and exposes manual node probing in the ChmlFrp console and Settings UI.

## Candidate filtering & ranking order

1. **Eligibility filter (`ordered_candidates`)**:
   - Excludes the failed/current `ACTIVE` node.
   - Excludes `offline` or quarantined nodes.
   - When any enabled tunnel plan uses `http` or `https`, excludes nodes with `web_supported = false`.
2. **Concurrent TCP probe (`probe_and_rank`)**:
   - Concurrently dials `node.host:probe_port` (3 attempts per node, averaged RTT in ms).
   - If **all** eligible candidates time out or fail, failover aborts immediately and logs a critical/error Activity entry instead of blindly falling back.
3. **STANDBY tolerance ranking (`sort_by_latency`)**:
   - Preferred `STANDBY` stays first when `standby_rtt <= min_rtt + probe_latency_tolerance_ms`.
   - Otherwise, candidates are ordered strictly by ascending average RTT.

## Probe settings (SQLite `provider_settings`, migration `0004`)

Configured in **Settings → 节点延迟探针** and stored via `PUT /api/v1/settings/providers`:

- `probe_port` (default `7000`): TCP port to probe on each node's `host` IP.
- `probe_timeout_ms` (default `2000`, min `100`): per-attempt TCP connect timeout in milliseconds.
- `probe_latency_tolerance_ms` (default `50`): latency band in milliseconds protecting `STANDBY` priority.

## WebUI & API

- `POST /api/v1/nodes/probe`: probes all online, non-quarantined ChmlFrp nodes and returns `node_name`, `area`, `web_supported`, `avg_rtt_ms`, and `fastest`.
- **ChmlFrp page**: adds **测量全部节点** toolbar button and **探针延迟** column highlighting the fastest reachable node.
